# Day 8 Reflection

**The most difficult concept.** The hardest concept for me was concurrency, in particular understanding why two requests that each look correct on their own can break things when they run at the same time. The "check if the seat is free, then book it" idea seemed obviously fine until I realized another user could slip in between the check and the write. I overcame it by slowing down and tracing two users through the code step by step on paper, then trying the same scenario with transactions and an atomic `UPDATE ... WHERE status = 'available'`. Seeing exactly one request win and the other get zero rows affected made it click. Adding a UNIQUE constraint as a safety net also showed me that the database can enforce rules even when my code has bugs.

**What I would improve in my capstone.** I received feedback using "Two stars and a wish". The stars were that my cache invalidation explanation was very clear and that my demo handled empty notes nicely. The wish was that I show the request in the Network tab when I create a note. I agree, because my demo showed the result but not what happened between the browser and the server. Next time I would open the Network tab and walk through the request, method, status code and response.

**What I will learn next.**First, I want to turn my API design into working code by building a real backend with Node.js and Express, starting with the nodejs.org guides and MDN's "Express/Node introduction". Next, I will replace in-memory storage with a real database so QuickNotes can store notes for real users, using the PostgreSQL tutorial and SQLBolt to learn SQL properly. After that, I will deepen my system design knowledge with The System Design Primer on GitHub and the ByteByteGo articles. Throughout, I will keep practising the basics on MDN Learn Web Development and JavaScript.info, because fluency comes from repetition.
